# multicpa-landing

Одностраничный лендинг MultiCPA на React и TypeScript. Сборка идёт через Vite.

На странице четыре экрана: первый со сменой слова, MULTI-TASKS, MULTI-BENEFITS с бегущей строкой и MULTIPLY WITH US. Тексты задач, преимуществ и блока multiply приходят с API уже на нужном языке. Подписи, которых в API нет, отдаёт i18next из словарей `en` и `ru`. Язык для этих подписей берётся из адреса, а если первый сегмент не язык — из `sessionStorage`. С первого экрана и с блока multiply открывается форма связи. Английская версия открывается на `/`, русская — на `/ru`. Номер экрана в адресе не хранится: его держит скролл и якорь, например `#join`.

## Архитектура

Облегчённый FSD: слой зависит только от слоёв ниже. `shared` не знает верхние слои.

| Слой       | Зачем                               | Что лежит                                             |
| ---------- | ----------------------------------- | ----------------------------------------------------- |
| `app`      | Запустить сайт и выбрать страницу   | Роутер, глобальные стили                              |
| `pages`    | Собрать экраны                      | Лендинг и страница 404                                |
| `widgets`  | Показать то, что видит пользователь | Четыре экрана, шапка, фон, прелоадер, футер, экран 404 |
| `features` | Обработать действие                 | Перелистывание экранов, контактная форма, смена языка  |
| `shared`   | Общее для слоёв выше                | Запросы, список языков, словари i18next, кнопки, логотип, иконки |

Схема страниц и связей — в [docs/architecture.md](docs/architecture.md).

## Роутинг

Роутер работает в data mode: `createBrowserRouter` и `RouterProvider`. Маршруты описаны в `src/app/router.tsx`.

Два маршрута:

| Путь      | Кто грузит данные                         | Что рисуется                                      |
| --------- | ----------------------------------------- | ------------------------------------------------- |
| `/:lang?` | `pages/landing/model/loader.ts`           | Лендинг. Ошибка лоадера — `errorElement`, страница 404 |
| `*`       | `pages/not-found/model/loader.ts`         | Та же страница 404                                |

Список языков лежит в `LOCALES` в `src/shared/config/locales.ts`. Сейчас это `en` и `ru`.

| Адрес                                       | Что происходит                                                                 |
| ------------------------------------------- | ------------------------------------------------------------------------------ |
| `/`                                         | Лендинг, язык `en`                                                             |
| `/ru`                                       | Лендинг, язык `ru`                                                             |
| `/en`                                       | Редирект на `/`                                                                |
| `/de` и другой неизвестный первый сегмент   | Сначала `changeLanguage(resolveLocale(path))`, потом 404 через `errorElement` |
| `/a/b` и любой путь длиннее одного сегмента | Лоадер 404: `changeLanguage(resolveLocale(path))`, затем страница 404          |

Лоадер лендинга до отрисовки делает так:

1. Если сегмент `en`, бросает `redirect("/")`.
2. Ждёт `i18n.changeLanguage(resolveLocale(pathname))`. Первый рендер сразу на нужном языке, в том числе на 404.
3. Если сегмент не входит в `LOCALES`, бросает ответ со статусом 404. Его рисует `errorElement`.
4. Иначе запоминает язык через `rememberLocale` и возвращает `{ lang, data }`. `data` — промис `Promise.all` из `getTasks`, `getBenefits` и `getMultiply`. Сигнал отмены запроса — `request.signal`.

Страница читает это так и ждёт промис в `Await`. Пока запросы идут, прелоадер смотрит на тот же промис через `useIsPending`.

```tsx
const { lang, data } = useLoaderData<typeof loader>()
```

`Await` отдаёт кортеж `[tasks, benefits, multiply]`. Типы ответов — `Tasks`, `Benefits` и `Multiply` рядом с функциями в `shared/api`.

Правила:

- Это обычные функции. Хук внутри `loader` не вызывается: `loader` выполняется до рендера.
- `POST /form` в этот `loader` не входит. Отправка — хук `useSendForm` из `shared/api`.
- Неизвестный язык и провал самого лоадера рисует `errorElement`, сейчас это страница 404. Ошибка внутри промиса `data` остаётся у `Await` и рисует его `errorElement`.
- Виджеты экранов данные сами не запрашивают. Они получают их со страницы.

## Интернационализация

Почти весь контент приходит из API уже на нужном языке. i18next нужен только для статики.

| Ключи              | Что это                                                         |
| ------------------ | --------------------------------------------------------------- |
| `header`           | Ссылки шапки                                                    |
| `cta`              | Все кнопки, в том числе `cta.takeMeBack` на 404                |
| `form`             | Плейсхолдеры, подсказка про обязательные поля, submit           |
| `modal`            | Тексты модалки успеха. `modal.close` — `aria-label` крестика    |
| `benefits.accent`  | Основа акцентного слова: `guarant` / `гаранти`                  |

Так же переводятся `aria-label`, `alt` и `title`: `aria-label={t('modal.close')}`.

Капс задаётся в CSS через `text-transform`. Звёздочка `*` у обязательного поля — отдельный `span`, в словарь она не входит.

### Как добавить перевод

Текст, который видит пользователь, в разметку не пишется. Если строка приходит с API, в словарь её не кладут. Если это статика из таблицы выше — её добавляют в оба словаря и читают через `t()`.

1. Выбери уже существующую группу: `header`, `cta`, `form`, `modal`, `benefits`. Новую группу заводи, только если строка ни в одну не ложится.
2. Добавь ключ в `en.json` и тот же ключ в `ru.json`, на том же месте. Имя ключа — английский `camelCase`. Пропущенный ключ в `en.json` поймает TypeScript: типы `t()` сняты с английского словаря.
3. В компоненте возьми `useTranslation` и подставь `t('group.key')`. Язык компонент не переключает: его меняет лоадер, когда меняется адрес. Кнопка языка — это ссылка на `/` или `/ru`.

```tsx
import { useTranslation } from 'react-i18next'

const JoinButton = () => {
  const { t } = useTranslation()

  return <button type="button">{t('cta.joinTheTeam')}</button>
}
```

```json
{
  "cta": {
    "joinTheTeam": "Join the team"
  }
}
```

В `ru.json` тот же ключ: `"joinTheTeam": "В команду"`.

Подпись для скринридера пишется так же, отдельным ключом: `aria-label={t('modal.close')}`, `alt={t('...')}`, `title={t('...')}`.

Капс в значение не зашивай: в словаре обычный регистр, в SCSS — `text-transform: uppercase`. Звёздочку обязательного поля в строку не включай, её рисует разметка:

```tsx
<span aria-hidden="true">*</span>
```

Акцент в заголовке с API не размечай в словаре. Передай в `renderTitle` весь текст и основу из `t('benefits.accent')`.

Новый язык — отдельно, см. раздел ниже: код в `LOCALES`, файл `xx.json`, импорт в `resources`. Без импорта словарь в бандл не попадёт.

### Файлы

| Файл                                      | Зачем                                                                                          |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `src/shared/i18n/en.json`, `ru.json`      | Словари. Структура ключей одинаковая                                                           |
| `src/shared/i18n/i18n.ts`                 | Конфиг: `resources`, `lng` и `fallbackLng: 'en'`, `supportedLngs: LOCALES`, `escapeValue: false`. Событие `languageChanged` пишет `<html lang>` |
| `src/shared/i18n/i18next.d.ts`            | Типы ключей `t()` берутся из `en.json`                                                         |
| `src/shared/config/locales.ts`            | `LOCALES`, `Locale`, `isLocale`. Это источник правды по списку языков                          |
| `src/shared/config/home-path.ts`          | `rememberLocale`, `resolveLocale`, `getHomePath`                                               |
| `src/main.tsx`                            | Один импорт конфига. Провайдер не нужен                                                        |

### Как язык попадает на экран

Адрес → лоадер → `i18n.changeLanguage(lang)` → `t()` читает нужный словарь → компоненты с `useTranslation()` перерисовываются → событие `languageChanged` ставит `<html lang>`.

### `resolveLocale`

Главная функция выбора языка. Путь из URL важнее, `sessionStorage` — только запасной вариант.

1. Путь пустой (`/`) → `en`.
2. Первый сегмент — язык из `LOCALES` (`/ru/...`) → этот язык.
3. Сегмент непонятный (`/de`, `/foo`) → язык из `sessionStorage`, иначе `en`.

`rememberLocale` пишет язык в `sessionStorage` только из лоадера лендинга, когда сегмент уже проверен и входит в `LOCALES`.

`getHomePath()` читает тот же `resolveLocale`: для `en` путь `/`, для остальных — `/<lang>`. Язык экрана 404 и ссылка «домой» берутся из одной функции, поэтому всегда совпадают.

### Акцент в заголовках из API

API присылает текст без разметки, поэтому `<Trans>` не подходит. `renderTitle(title, t('benefits.accent'))` ищет основу без учёта регистра и выделяет слово целиком. Если сервер поменяет формулировку, подсветка пропадёт, вёрстка останется целой.

### Почему так

- Нет `languageDetector`: язык берётся из URL, английский основной.
- Нет http-backend: словари лежат в бандле, прелоадер и так ждёт запросы к API.
- `<Trans>` не нужен: строки простые.
- `await changeLanguage` стоит в async-лоадере: первый рендер сразу на нужном языке.

### Новый язык

Маршрут менять не нужно. Три шага:

1. Добавить код в `LOCALES`.
2. Создать `xx.json` с той же структурой ключей.
3. Импортировать его в `resources` в `i18n.ts`. Сам файл не подключится.

## Запросы

Три GET вызываются из лоадера лендинга. Общая функция — `getJson` в `src/shared/api/request.ts`: она подставляет язык в путь, шлёт `x-api-key`, проверяет статус и разбирает тело схемой Zod.

| Функция       | Файл                         | Эндпоинт               |
| ------------- | ---------------------------- | ---------------------- |
| `getTasks`    | `src/shared/api/tasks.ts`    | `GET /{lang}/tasks`    |
| `getBenefits` | `src/shared/api/benefits.ts` | `GET /{lang}/benefits` |
| `getMultiply` | `src/shared/api/multiply.ts` | `GET /{lang}/multiply` |

Наружу функции отдаёт только `src/shared/api/index.ts`. Импорт из конкретных файлов не используется.

Адрес и ключ читает `getEnv` из `src/shared/config/env.ts`.

```ts
export const getJson = async <T>(
  path: string,
  lang: Locale,
  schema: z.ZodType<T>,
  signal?: AbortSignal,
): Promise<T> => {
  const response = await fetch(`${getEnv('VITE_API_URL')}/${lang}/${path}`, {
    headers: { 'x-api-key': getEnv('VITE_API_KEY') },
    signal,
  })

  if (!response.ok) {
    throw new Error(`Request failed: ${response.status}`)
  }

  const json: unknown = await response.json()

  return schema.parse(json)
}
```

`getTasks`, `getBenefits` и `getMultiply` передают в `getJson` свой путь и схему. Лоадер их не меняет: он уже собирает три вызова в один промис.

## Модель работы с ветками в Git

Задача стартует, когда за ней закреплён ответственный и её перенесли в колонку In progress.

На проекте упрощённый git-flow, три вида веток:

- `master` — стабильный код, который уходит в продакшен.
- `develop` — основная ветка разработки, куда собираются готовые фичи.
- feature-ветка под задачу. Создаётся от `develop` и вливается обратно в `develop`. Имя — по названию фичи, например `main-form-component`.

Отдельных веток `release` и `hotfix` нет: `develop` сливается в `master` по договорённости.

**Коммиты в feature-ветке** именуются `${feature part} ${action}`: сначала часть фичи, потом действие. Например, `form validation add` или `submit button fix`. Часть фичи стоит в начале, чтобы в `git log` коммиты одной части стояли рядом и читались без разбора глагола.

**Слияние в `develop`.** Автор открывает pull request из feature-ветки. Второй разработчик проверяет его и одобряет. Конфликты при слиянии исправляет тот, кто инициировал merge. Когда PR открыт, задача переходит в колонку In review.

**Слияние в `master`.** Автор открывает PR в `master`, код-ревью делает куратор проекта. Момент слияния назначает куратор на митинге. В чате куратора тегают, когда работа касается ветки `master`.

## Окружение и API

### Настройка

1. Скопируй `.env.example` в `.env` в корне проекта.
2. Впиши в `VITE_API_KEY` ключ из ТЗ.
3. Перезапусти `npm run dev`.

> `.env` в git не коммитится, он есть в `.gitignore`.

### Переменные

| Переменная     | Описание                                         |
| -------------- | ------------------------------------------------ |
| `VITE_API_URL` | Базовый адрес API                                |
| `VITE_API_KEY` | Ключ доступа, передаётся в заголовке `x-api-key` |

### Правила запросов

- Каждый запрос отправляется с заголовком `x-api-key`.
- Язык передаётся в пути: `en` или `ru`, по умолчанию `en`.
- Документация API: [Swagger](https://cpa-server-vtel.onrender.com/api-docs/)

### Эндпоинты

- `GET /{lang}/benefits` — тексты экрана MULTI-BENEFITS
- `GET /{lang}/tasks` — тексты экрана MULTI-TASKS
- `GET /{lang}/multiply` — тексты экрана MULTIPLY WITH US
- `POST /form` — заявка из контактной формы

Тело `POST /form`, JSON:

| Поле      | Обязательное | Значение                           |
| --------- | ------------ | ---------------------------------- |
| `name`    | нет          | Имя, строка                        |
| `method`  | да           | `telegram`, `whatsapp` или `email` |
| `contact` | да           | Контакт выбранным способом, строка |

### Использование в коде

Переменные читаются в одном месте, в `src/shared/config/env.ts`. Пустая строка и нестроковое значение считаются ошибкой:

```ts
export const getEnv = (name: 'VITE_API_URL' | 'VITE_API_KEY'): string => {
  const value: unknown = import.meta.env[name]

  if (typeof value !== 'string' || value === '') {
    throw new Error(`${name} is not set`)
  }

  return value
}
```

Типы `import.meta.env` приходят из `vite/client`: он подключён в `types` в `tsconfig.app.json`.

### Правила

- В коде окружение берётся через `getEnv` из `shared/config/env`.
- Новую переменную нужно добавить в `.env.example`, в аргумент `getEnv` и в таблицу выше.

## Алиасы

Базовый алиас `@` указывает на `src`. Он настроен и в Vite, и в TypeScript (`paths` в `tsconfig.app.json`).

Импорт из корня исходников выглядит так:

```ts
import { something } from "@/shared/ui";
```

В `vite.config.ts` алиас вынесен в `resolvePath`, чтобы туда же можно было добавить следующие пути.

## Сборка

В продакшен-сборке Vite 8 удаляет `console` и `debugger`. Это задано через Rolldown, а не через старый синтаксис esbuild:

```ts
build: {
  rolldownOptions: {
    output: {
      minify: {
        compress: {
          dropConsole: true,
          dropDebugger: true,
        },
      },
    },
  },
},
```

## Что сознательно не включено

**React Compiler** не подключён. Рендеры и оптимизацию сначала разбираем вручную. Компилятор можно добавить позже, когда эта практика будет не нужна.

**Proxy** в Vite на старте не настраивался: нужды в нём пока нет. Если появится CORS или захочется упростить запросы к API, proxy добавляется в `vite.config.ts` на этапе реализации запросов.

**Biome** настроен в `biome.json`: пресет recommended, домен React и запрет импортов между слоями FSD. Проверка — `npm run check`, правка — `npm run check:fix`.
